# Часть 3. Маршрутизация (URLs) и представления (Views)

## 1. Базовое Представление (View)
Представление — это функция (или класс), которая принимает запрос пользователя и **обязательно** возвращает ответ.

Файл: **`women/views.py`**
```python
from django.http import HttpResponse

def index(request):
    # request — это объект HttpRequest (содержит данные о куках, сессии, GET/POST параметрах)
    return HttpResponse("Страница приложения women.")

def categories(request):
    # В HttpResponse можно передавать сырой HTML-код
    return HttpResponse("<h1>Статьи по категориям</h1>")
```

Аргумент `request` в представлениях (Views) — это обязательный объект-контейнер, в который Django упаковывает всю информацию, пришедшую от браузера пользователя (тип запроса, данные из форм, авторизован ли пользователь, файлы куки и т.д.). Без него функция не сможет обработать входящий запрос.

## 2. Правильная маршрутизация через `include()`
**Никогда не прописывайте все пути приложений в главном файле настроек сайта!** Это нарушает независимость кода. Правильный подход — связать главный `urls.py` с локальным `urls.py` внутри самого приложения.

### Шаг A. Настройка главного файла проекта
Файл: **`sitewomen/urls.py`**
```python
from django.contrib import admin
from django.urls import path, include  # Обязательно импортируем include

urlpatterns = [
    path('admin/', admin.site.urls),
    
    # Говорим Django: "Если адрес начинается с women/, ищи продолжение в приложении women":
    path('women/', include('women.urls')), 
]
```

### Шаг B. Создание локального файла путей в приложении
Создайте файл **`urls.py`** вручную прямо внутри папки **`women/`**.

Файл: **`women/urls.py`**
```python
from django.urls import path
from women import views  # Импортируем модуль views целиком — это лучшая практика!

urlpatterns = [
    # Пустая строка '' означает Главную страницу внутри этого префикса
    # Полный URL будет: http://127.0.0.1:8000/women/
    path('', views.index),
    
    # Полный URL будет: http://127.0.0.1:8000/women/cats/
    path('cats/', views.categories),
]
```

## ⚠️ Важные нюансы и подводные камни 

### 1. Как сделать Главную страницу ВСЕГО сайта?
Если вам нужно, чтобы функция `index` открывалась сразу по адресу `http://127.0.0.1:8000/` (без слова `women/`), в главном файле проекта (`sitewomen/urls.py`) укажите пустую строку:
```python
path('', include('women.urls')),  # Теперь сайт открывается сразу на корневом адресе
```

### 2. Подводный камень: Ошибка импорта в PyCharm
Если вы импортируете `from women import views`, а редактор (PyCharm) подчеркивает слово `women` красным цветом — проект все равно запустится. 
* **Почему это происходит:** PyCharm считает "корнем" проекта самую верхнюю папку, а не ту, где лежит `manage.py`.
* **Как исправить:** Кликните правой кнопкой мыши по папке `sitewomen` (внешней) → **Mark Directory as** → **Sources Root**. Красное подчеркивание исчезнет.

### 3. Правило «Финального слэша»
Всегда пишите слэш `/` в конце путей в функции `path()` (например, `'cats/'`, а не `'cats'`). 
* В Django по умолчанию включена настройка `APPEND_SLASH = True`. 
* Если пользователь введет в браузере `/women/cats`, Django увидит, что в коде прописано `'cats/'`, автоматически сделает редирект (перенаправление) на `/women/cats/` и страница откроется. Если вы забудете слэш в коде, ссылки начнут конфликтовать и ломаться.

### 4. Импорт модуля целиком vs Импорт отдельных функций
* **Плохо:** `from women.views import index, categories, about, contact` (список будет бесконечным, легко запутаться).
* **Хорошо:** `from women import views` и затем обращение через точку: `views.index`, `views.categories`. Код становится чистым и понятным.
