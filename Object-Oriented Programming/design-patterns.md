# Паттерны проектирования 

✅ **Паттерны проектирования** — это проверенные временем решения типовых задач. Они **не являются** конкретным кодом на каком-либо языке программирования и **не описывают** алгоритм решения задачи. Паттерны предлагают общую концепцию решения той или иной проблемы, возникающей при написании программ.

✅ **В классическом понимании** выделяют 23 основных паттерна проектирования, которые делятся на три главные категории:

+ **порождающие** — описывают способы создания объектов
+ **структурные** — описывают способы организации классов и объектов в более сложные структуры
+ **поведенческие** — описывают способы взаимодействия объектов и распределения обязанностей между ними

# Синглтон

✅ **Синглтон** — это **порождающий** паттерн проектирования, который гарантирует, что объект некоторого класса существует в единственном экземпляре, и предоставляет глобальную точку доступа к нему.

✅ **Возможная реализация синглтона**:

``` python
class Singleton:
    _instances = {}

    def __new__(cls, *args, **kwargs):
        if cls not in cls._instances:
            cls._instances[cls] = object.__new__(cls)

        return cls._instances[cls]
```
                 
✅ **Объекты-синглтоны** Python:

+ константа `None`
+ константа `True`
+ константа `False`
+ константа `NotImplemented`
+ литерал `...`

✅ **Плюсы паттерна**:

+ **Контроль экземпляров**. Паттерн гарантирует, что существует строго один объект определенного класса.
+ **Глобальный доступ**. Предоставляет удобную точку доступа к объекту из любой части программы.
+ **Ленивая инициализация**. Объект создается только один раз в момент первого обращения, что позволяет экономить ресурсы.
+ **Совместное использование ресурсов**. Все части программы работают с одним и тем же состоянием. Это позволяет, например, использовать одни и те же настройки во всей программе.

✅ **Минусы паттерна**:

+ **Глобальное состояние**. Любая часть кода может изменить состояние объекта, что затрудняет отслеживание ошибок.
+ **Сложность тестирования**. Синглтоны затрудняют написание тестов, так как сохраняют свое состояние между ними.
+ **Скрытые зависимости и сильная связность кода**. Классы, использующие синглтон, неявно зависят от него, из-за чего становится сложно вносить в них изменения.
+ **Проблемы при многопоточности**. В многопоточной среде паттерн требует специальной реализации, чтобы предотвратить одновременное создание нескольких экземпляров.

# Фабричный метод

✅ **Фабричный метод** — это **порождающий паттерн** проектирования, который определяет общий интерфейс для создания экземпляров класса, позволяя дочерним классам изменять тип создаваемого объекта.

✅ **Паттерн фабричный метод** помогает решить проблему жесткой привязки к конкретным классам создаваемых объектов. Для этого он предлагает выделить две группы объектов:

+ создатели
+ продукты

Создатели, как правило, содержат логику для работы с продуктами и один фабричный метод, который используется для создания этих продуктов. Сами продукты — это объекты, создаваемые фабричными методами.

✅ **Паттерн фабричный метод** следует применять, когда заранее неизвестно, какие типы продуктов и в каком количестве будут использоваться. Если потребуется добавить новый продукт, достаточно будет определить для него соответствующего создателя, а не вносить изменения в существующий код, что могло бы повлечь за собой цепочку ошибок.

✅ Ярким примером реализации **паттерна фабричный метод** являются классы `Path` и `PurePath` встроенного модуля `pathlib`. Этот модуль предназначен для работы с путями операционной системы и содержит следующую иерархию классов:

![](https://ucarecdn.stepik.net/a4c0b2ae-65d7-490d-8ce5-15871567e57b/.jpg)

Здесь классы `Path` и `PurePath` являются создателями, а все остальные классы — продуктами. В качестве фабричного метода у них выступает метод `__new__()`, который сам определяет, экземпляр какого класса нужно создать. Тип экземпляра зависит от используемой операционной системы.

✅ **Плюсы паттерна**:

+ **Слабая связанность**. Детали зависят от абстракций, а не от конкретных реализаций, благодаря чему соблюдается принцип инверсии зависимостей.
+ **Инкапсуляция**. Логика создания объектов изолирована в одном месте, что упрощает поддержку и изменение кода.
+ **Упрощение тестирования**. Благодаря тому, что создание объекта вынесено в отдельный метод, можно легко подменить реальную фабрику на тестовую и провести тесты, не затрагивая реальный объект.
  
✅ **Минусы паттерна**:

+ **Усложнение архитектуры**. Паттерн может привести к созданию сложной иерархии классов, так как для каждого продукта нужен отдельный создатель.
+ **Излишняя сложность для простых задач**. Если создаваемые объекты имеют простую структуру или процесс их создания полностью совпадает, использование фабричного метода может быть избыточным.

# Строитель

✅ **Строитель** — это **порождающий** паттерн проектирования, который позволяет создавать сложные объекты поэтапно, отделяя процесс конструирования объекта от его представления.

✅ **Паттерн строитель** помогает решить проблему перегруженности конструктора класса параметрами и необходимости помнить о том, какие из них являются обязательными и в каком порядке нужно указывать аргументы. Для этого он предлагает определить отдельный класс-строитель для создания объекта и наделения его атрибутами. Сначала этот класс создает пустой объект, а затем постепенно добавляет в него атрибуты. Как правило, это происходит с помощью методов с префиксами `set`, `add` или другими похожими по смыслу. В самом конце с помощью отдельного метода класс возвращает готовый экземпляр. Этот метод перед возвратом экземпляра может выполнять какие-либо дополнительные действия, например, валидацию атрибутов.

✅ Одним из хороших примеров **паттерна строитель** в Python является встроенный модуль `argparse`, который предназначен для обработки аргументов командной строки. Для выполнения этой цели сначала создается пустой экземпляр специального объекта-парсера, с помощью которого выполняется обработка аргументов, а затем в этот объект добавляются все необходимые аргументы. После этого с помощью отдельного метода считываются значения аргументов.

✅ **Плюсы паттерна**:

+ **Пошаговое создание сложных объектов**. Паттерн позволяет создавать объекты поэтапно, что дает полный контроль над их состоянием.
+ **Читабельность**. Код инициализации объектов становится гораздо чище и понятнее.
+ **Переиспользование**. Один и тот же класс-строитель можно использовать для создания разных представлений объектов.
+ **Инкапсуляция**. Процесс создания скрыт от внешнего кода, ему доступны только удобные методы для инициализации объектов.

✅ **Минусы паттерна**:

+ **Усложнение кода**. Паттерн увеличивает количество создаваемых классов, что может быть избыточным для простых объектов.
+ **Зависимость**. В некоторых случаях внешний код может быть жестко привязан к классу-строителю.

# Адаптер

✅ **Адаптер** — это **структурный** паттерн проектирования, который позволяет объектам с несовместимым интерфейсом работать вместе.

✅ **Паттерн адаптер** помогает решить проблему несовместимости интерфейсов. Например, если мы подключим сторонний сервис, классы которого имеют интерфейс, отличный от нашего, а также методы этих классов возвращают результат в другом формате или других единицах измерения, то программа может работать неправильно. 

Для решения этой проблемы паттерн адаптер предлагает определить отдельный класс-адаптер, который будет иметь интерфейс, совместимый с нашей программой. Методы этого класса должны будут обращаться к методам несовместимого класса для выполнения необходимых действий.

✅ Методы могут отличаться не только названием и форматом возвращаемого значения, но и сигнатурой. В этом случае для адаптации сигнатуры класс-адаптер может принимать дополнительные аргументы при создании экземпляра.

✅ Примером **паттерна адаптер** в Python является класс `Path` встроенного модуля `pathlib`, который используется для работы с путями операционной системы. Он может использоваться в качестве аргумента функции `open()`, хотя аргументом этой функции должна быть строка.

Класс `Path` имеет магический метод `__fspath__()`, который вызывается автоматически у всех классов путей и возвращает путь в виде строки, что позволяет легко использовать эти классы в качестве аргумента функции `open()` и других похожих функций. Метод `__fspath__()`, по сути, и выступает в качестве адаптера.

✅ **Плюсы паттерна**:

+ **Использование несовместимых классов**. Основное преимущество паттерна — возможность обеспечить взаимодействие классов с разными интерфейсами без изменения их кода.
+ **Повторное использование**. Паттерн позволяет использовать устаревший код или сторонние библиотеки, интерфейс которых нельзя переписать.
+ **Разделение ответственности**. Бизнес-логика может быть сфокусирована на своих задачах, а адаптер возьмет на себя работу по обеспечению взаимодействия интерфейсов.
  
✅ **Минусы паттерна**:

+ **Увеличение количества классов**. Для каждого несовместимого интерфейса может потребоваться свой адаптер.
+ **Сложность при изменениях**. Если логика адаптируемого интерфейса слишком сильно отличается от логики интерфейсов основной программы, то реализация адаптера может стать слишком громоздкой и трудной для поддержки.
+ **Накладные расходы**. Каждый вызов осуществляется через дополнительный слой — адаптер, что добавляет небольшие накладные расходы. Это может быть критичным в высоконагруженных сервисах.

# Декоратор

✅ **Декоратор** — это **структурный** паттерн проектирования, который позволяет добавлять объектам новый функционал, не меняя их исходную структуру.

✅ **Паттерн декоратор** помогает решить проблему расширения поведения объектов. Без его применения по мере добавления новых возможностей количество классов начнет сильно разрастаться, так как нужно будет учесть все возможные комбинации возможностей. Также у каждого из этих классов начнет усложняться реализация всех необходимых методов. 

Чтобы решить эту проблему, паттерн декоратор предлагает использовать композицию вместо наследования. Для этого необходимо выделить отдельные классы с такой же структурой, как и у исходного класса. При создании экземпляра эти классы должны принимать экземпляр декорируемого класса и расширять его поведение в соответствующих методах.

✅ В Python **паттерн декоратор** встроен непосредственно в синтаксис языка. Для его применения над соответствующим объектом необходимо указать функцию или класс-декоратор, предварив их символом `@`.

✅ **Декоратор Python** не является классическим примером паттерна декоратор, но он предоставляет широкие возможности по расширению функционала объектов без вмешательства в их исходный код. Более того, такое применение декоратора намного удобнее, чем вызов конструктора класса-декоратора с передачей ему декорируемого объекта.

✅ Python содержит довольно большое количество встроенных декораторов: `@property`, `@staticmethod`, `@classmethod`, `@singledispatchmethod`, `@contextmanager`, `@lru_cache` и множество других.

✅ **Плюсы паттерна**:

+ **Гибкость**. Декоратор позволяет добавлять объекту новый функционал «на лету» во время выполнения программы.
+ **Композиция вместо наследования**. Декоратор избавляет от необходимости создавать огромное количество подклассов под каждую комбинацию свойств.
+ **Множественность оберток**. Можно применять сразу несколько декораторов, наслаивая их друг на друга в любой комбинации.
+ **Единый интерфейс**. Декораторы и декорируемые объекты имеют общий интерфейс, поэтому внешнему коду неважно, с каким именно объектом он работает.

✅ **Минусы паттерна**:

+ **Обилие классов**. Код может стать перегруженным из-за большого количества однотипных классов-декораторов.
+ **Сложность отладки**. Поведение многократно обернутого объекта бывает трудно отследить.
+ **Сложность конфигурации**. Создание объекта с помощью множества оберток намного сложнее, чем простой вызов конструктора.
+ **Порядок декораторов**. В некоторых случаях важно соблюдать порядок применения декораторов, что повышает хрупкость кода.
