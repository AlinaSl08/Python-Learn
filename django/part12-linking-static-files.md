# Подключение статических файлов (Static Files) в Django

**Статические файлы** — это неизменяемые файлы оформления сайта: CSS-стили, JavaScript-скрипты, изображения, шрифты и т. д.

* Полезные ссылки: [Курс по HTML + CSS](https://rutube.ru/plst/534428), [Bootstrap](https://getbootstrap.com), [Документация по фильтрам и тегам](https://docs.djangoproject.com/en/4.2/ref/templates/builtins/).

---

## 1. Режимы работы со статикой и настройки (`settings.py`)

Django работает со статическими файлами по-разному в зависимости от режима запуска сервера:

1. **Режим отладки (`DEBUG = True`):** Django автоматически ищет статику в папках `static` внутри всех приложений из `INSTALLED_APPS`.
2. **Режим эксплуатации (`DEBUG = False`):** Реальный веб-сервер берет всю статику из **одной общей папки проекта**. Чтобы собрать туда все файлы из разных приложений, перед деплоем выполняют команду:
   ```bash
   python manage.py collectstatic
   ```

### Основные настройки в `settings.py`:
* **`INSTALLED_APPS`** — обязательно должна быть подключена строка `'django.contrib.staticfiles'`.
* **`STATIC_URL`** — префикс URL-адреса для статических файлов (например, `'static/'`). Создается автоматически.
* **`STATIC_ROOT`** — путь к общей папке проекта, куда команда `collectstatic` соберет всю статику для боевого сервера.
* **`STATICFILES_DIRS`** — список нестандартных путей, где Django должен дополнительно искать статику при отладке и сборе:
  ```python
  STATICFILES_DIRS = [BASE_DIR / 'static']
  ```

## 2. Структура папок для статики

Чтобы избежать конфликтов имен между файлами разных приложений, внутри папки `static` приложения создается подкаталог **с именем самого приложения** (пространство имен):

```text
women/
└── static/
    └── women/
        ├── css/
        │   └── styles.css
        ├── js/
        └── images/
```

## 3. Подключение статики в шаблонах (`{% load static %}`)

Чтобы использовать статические файлы в HTML-шаблоне (например, `base.html`), нужно выполнить два шага:

1. В начале шаблона загрузить библиотеку тегов: `{% load static %}`
2. Сформировать путь к файлу с помощью тега: `{% static 'путь_от_папки_static' %}`

**Пример подключения CSS в `base.html`:**
```html
{% load static %}
<!DOCTYPE html>
<html>
<head>
    <link type="text/css" href="{% static 'women/css/styles.css' %}" rel="stylesheet" />
</head>
```
*В итоговом HTML это превратится в:* `<link type="text/css" href="/static/women/css/styles.css" rel="stylesheet" />`

## 4. Примеры форматирования контента (фильтры и `autoescape`)

В уроке также разобрана комбинация фильтров и тегов для красивого вывода текста статей:

```html
{% autoescape off %}
    {{ p.content|linebreaks|truncatewords:50 }}
{% endautoescape %}
```

* **`truncatewords:50`** — обрезает текст, оставляя только первые 50 слов.
* **`linebreaks`** — преобразует переносы строк (`\n`) в HTML-теги абзацев `<p>` и переносов `<br>`.
* **`{% autoescape off %} ... {% endautoescape %}`** — отключает экранирование HTML-тегов внутри переменной (чтобы теги вроде `<h1>` внутри текста статьи применялись браузером как разметка, а не выводились как обычный текст).

## 5. Локальный запуск при `DEBUG = False`

Если локально переключить в `settings.py` параметр `DEBUG = False`, встроенный тестовый сервер Django перестанет отдавать статические файлы и оформление пропадет. Чтобы протестировать сайт локально без режима отладки, нужно запускать сервер с флагом **`--insecure`**:

```bash
python manage.py runserver --insecure
```
