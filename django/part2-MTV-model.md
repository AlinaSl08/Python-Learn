# Часть 2. Архитектура MTV и создание приложений в Django

## 1. Как Django обрабатывает запросы (Паттерн MTV)

Django работает по принципу разделения логики, данных и внешнего вида сайта. Этот паттерн называется **MTV (Model-View-Template)**.

### Схема прохождения запроса:
```text
[Пользователь в браузере] 
       │
       ▼ (вводит URL, например: /women/madonna/)
┌────────────────────────────────────────────────────────┐
│ 1. urls.py (Маршрутизатор)                             │ -> Ищет совпадение по шаблону.
└──────┬─────────────────────────────────────────────────┘    Если не нашел — ошибка 404.
       │ (Совпадение найдено!)
       ▼
┌────────────────────────────────────────────────────────┐
│ 2. views.py (Представление / Контроллер)               │ -> «Мозг» страницы. Запрашивает данные.
└──────┬───────────────────▲─────────────────────────────┘
       │                   │
       │ (Запрос данных)   │ (Возврат данных)
       ▼                   │
┌──────────────────────────┴─────────────────────────────┐
│ 3. models.py (Модель / База данных)                    │ -> Извлекает нужные строки из БД.
└────────────────────────────────────────────────────────┘
       │
       ▼ (Передача данных в шаблон)
┌────────────────────────────────────────────────────────┐
│ 4. templates/ (Шаблон HTML)                            │ -> Рендерит «чистый» HTML-код.
└──────┬─────────────────────────────────────────────────┘
       │
       ▼ (Готовая HTML-страница)
[Отображение в браузере пользователя]
```

## 2. Создание первого приложения

По философии Django каждая логически независимая часть сайта (форум, блог, опросы) должна быть **отдельным изолированным приложением**, которое можно легко перенести в другой проект.

### Команда для создания приложения:
Перейдите в терминале в каталог, где лежит файл `manage.py`, и выполните:
```bash
python manage.py startapp women
```
*(где `women` — имя вашего нового приложения).*

### Структура созданного пакета:
* **`migrations/`** — папка, где хранятся файлы миграций для базы данных.
* **`admin.py`** — настройки стандартной админ-панели Django для этого приложения.
* **`apps.py`** — конфигурационный файл самого приложения (содержит класс настроек).
* **`models.py`** — описание таблиц базы данных в виде Python-классов (ORM).
* **`tests.py`** — модуль для написания автоматических тестов.
* **`views.py`** — функции или классы представлений (обработчики запросов).

## 3. Регистрация приложения в проекте

Чтобы Django «увидел» новое приложение, его необходимо обязательно зарегистрировать в файле настроек проекта.

1. Откройте файл пакета конфигурации: **`sitewomen/settings.py`**
2. Найдите список `INSTALLED_APPS` и добавьте путь к классу конфигурации вашего приложения:

```python
INSTALLED_APPS = [
    # ... стандартные приложения Django ...
    
    # Наше новое приложение (лучшая практика указания полного пути):
    'women.apps.WomenConfig', 
]
```

> 📌 **Почему именно `'women.apps.WomenConfig'`?** 
> Можно написать просто `'women'`, и это будет работать. Однако указание полного пути через класс `WomenConfig` из файла `apps.py` является более правильным, так как Django сразу подтянет все специфические внутренние настройки приложения без лишних проверок в будущем.
