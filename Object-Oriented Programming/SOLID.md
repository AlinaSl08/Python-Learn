# Принцип единственной ответственности

✅ **Принципы SOLID** — пять основных правил объектно-ориентированного программирования, целью которых является написание понятного, гибкого и легко поддерживаемого кода.

✅ **Принципы SOLID** были озвучены **Робертом Мартином** в начале 2000-х годов, а акроним SOLID был придуман и введен Майклом Фэзерсом в 2004 году.

✅ Каждая буква акронима **SOLID** — это первая буква названия одного из принципов:

+ **S** (Single Responsibility Principle, SRP) — принцип единственной ответственности
+ **O** (Open/Closed Principle, OCP) — принцип открытости/закрытости
+ **L** (Liskov Substitution Principle, LSP) — принцип подстановки Барбары Лисков
+ **I** (Interface Segregation Principle, ISP) — принцип разделения интерфейсов
+ **D** (Dependency Inversion Principle, DIP) — принцип инверсии зависимостей

✅ **Принцип единственной ответственности** — это принцип, согласно которому каждый модуль должен иметь только одну причину для изменения. Причиной для изменения обычно называют изменение требований к приложению, из-за которых приходится менять его код, а модулем — связанный набор функций и структур данных.

✅ Изменений могут желать несколько источников требований, поэтому, говоря о причине для изменения, обычно имеют в виду группу источников, которую называют **актором**. **Актор** — это роль, которую играет группа источников требований по отношению к приложению.

✅ Для соблюдения **принципа единственной ответственности** модули проектируются так, чтобы каждый из них отвечал только за одного актора, то есть имел только одну ответственность и причину для изменения.

✅ **Божественный объект** — это объект, который имеет слишком много ответственностей. Он считается антипаттерном, которого можно избежать благодаря соблюдению принципа единственной ответственности.
