# Часть 5. Django URL Routing: Конвертеры путей, Пространства имен и Обратное разрешение

Маршрутизация в Django связывает URL-адреса с функциями представлений через список `urlpatterns` с помощью `path()` и `re_path()`.

## 1. Алгоритм обработки запроса
Django обрабатывает запросы последовательно: определяет Root URLconf, загружает список `urlpatterns`, перебирает паттерны по порядку до первого совпадения с `path_info`, вызывает соответствующий View с аргументами и обрабатывает ошибки при отсутствии совпадений.

## 2. Встроенные конвертеры путей
Синтаксис `<тип:имя>` извлекает динамические параметры. Поддерживаются стандартные типы: `str`, `int`, `slug`, `uuid`, `path`. Порядок маршрутов важен (например, `int` должен идти выше общего `slug`).

## 3. Регулярные выражения в `re_path()`
Применяются для сложных условий (`(?P<name>pattern)`). Параметры во view всегда передаются как строки.

## 4. Создание кастомных конвертеров
Позволяют инкапсулировать валидацию через классы с методами `regex`, `to_python` и `to_url`, регистрируемые функцией `register_converter()`.

## 5. Подключение других URLconf и kwargs
Функция `include()` разбивает маршруты на модули. Дополнительные `kwargs` передают статические параметры во view.

## 6. Обратное разрешение и Пространства имен
Использование функции `reverse` или тега `{% url %}` исключает жесткое кодирование ссылок. Пространства имен (`app_name` и `namespace`) предотвращают конфликты имен в разных приложениях.

# 💡 Нюансы
* `path()` приводит типы автоматически, а `re_path()` передает все как строки.
* Ошибки `ValueError` в `to_python` воспринимаются роутером как несовпадение пути, а не падение сервера.
* `urlpatterns` компилируются один раз при старте приложения.
* Параметры GET/POST и HTTP-методы не участвуют в роутинге.
