# Основы работы с ORM Django (QuerySet и Manager)

## 1. Подготовка и менеджер записей (`objects`)
* **Запуск консоли с отображением SQL-запросов:**
  ```bash
  python manage.py shell_plus --print-sql
  ```
* **`objects`** — статический атрибут класса модели (объект класса `Manager`), через который выполняются все операции с базой данных.

---

## 2. Создание записей: метод `create()`
Позволяет создать запись и сразу сохранить её в БД без вызова `save()`.
```python
# Создание с сохранением в переменную
w = Women.objects.create(title='Ума Турман', content='Биография Ума Турман')
w.pk  # Вернет ID созданной записи

# Создание без присваивания переменной
Women.objects.create(title='Кира Найтли', content='Биография Киры Найтли')
```

---

## 3. Выборка всех записей: метод `all()`
Возвращает ленивую коллекцию объектов — **`QuerySet`**.

### Красивое отображение объектов в консоли
По умолчанию объекты выводятся как `<Women: Women object (1)>`. Чтобы выводить заголовок, нужно переопределить метод `__str__` в модели:
```python
class Women(models.Model):
    # ... поля модели ...
    def __str__(self):
        return self.title
```

### Работа с полученным `QuerySet`
* **Получение по индексу или срезу:**
  ```python
  w = Women.objects.all()[0]    # Первый объект
  w = Women.objects.all()[:3]   # Срез первых трех объектов
  ```
  > **Важно:** `QuerySet` ленив. Реальный SQL-запрос отправляется в БД только в момент обращения к данным (при выводе в консоль, итерации и т.д.).
* **Перебор в цикле:**
  ```python
  for w in Women.objects.all():
      print(w)
  ```

## 4. Фильтрация записей: `filter()` и `exclude()`
Используются для выборки записей по условиям (аналог SQL `WHERE`), чтобы не загружать в память всю таблицу.

* **`filter()`** — выбирает записи, **соответствующие** условию.
* **`exclude()`** — выбирает записи, **не соответствующие** условию.
  ```python
  Women.objects.filter(title='Энн Хэтэуэй')  # Точное совпадение
  Women.objects.exclude(pk=2)                # Все записи, кроме id=2
  ```

### Несколько условий (логическое `И` / `AND`)
Условия, перечисленные через запятую, объединяются в SQL через оператор `AND`:
```python
Women.objects.filter(pk__in=[2, 5, 11, 12], is_published=1)
```
*(Для логического `ИЛИ` / `OR` используется класс `Q`)*.

## 5. Популярные модификаторы поиска (Field Lookups)
В Django нельзя писать выражения вида `pk > 2` внутри `filter()`. Вместо этого к имени поля через двойное подчеркивание (`__`) добавляются специальные суффиксы (lookups):

| Lookup | Описание | Пример |
| :--- | :--- | :--- |
| `__gte` | Больше или равно (`>=`) | `Women.objects.filter(pk__gte=2)` |
| `__gt` | Строго больше (`>`) | `Women.objects.filter(pk__gt=2)` |
| `__lte` | Меньше или равно (`<=`) | `Women.objects.filter(pk__lte=5)` |
| `__lt` | Строго меньше (`<`) | `Women.objects.filter(pk__lt=5)` |
| `__contains` | Поиск подстроки (с учетом регистра) | `Women.objects.filter(title__contains='ли')` |
| `__icontains` | Поиск подстроки (без учета регистра)* | `Women.objects.filter(title__icontains='ЛИ')` |
| `__in` | Проверка вхождения в список значений | `Women.objects.filter(pk__in=[2, 5, 11])` |

> **\* Особенность SQLite:** В СУБД SQLite регистронезависимый поиск (`__icontains`) не работает для не-ASCII символов (включая кириллицу) — запрос вернет пустой список. Для латиницы поиск в SQLite всегда регистронезависим.

## 6. Получение одной записи: метод `get()`
В отличие от `filter()`, который всегда возвращает список (`QuerySet`), метод `get()` используется для получения **ровно одного** объекта (обычно по `pk` или уникальному полю):
```python
Women.objects.get(pk=2)
```
