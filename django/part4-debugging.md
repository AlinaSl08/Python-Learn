# Часть 4. Настройка режима отладки (Debug) в PyCharm

По умолчанию команда `python manage.py runserver` запускает сервер в обычном режиме. Чтобы иметь возможность ставить точки останова (Breakpoints) и построчно проверять код, необходимо настроить конфигурацию запуска в PyCharm.

## 1. Пошаговая настройка конфигурации отладки

1. В правом верхнем углу PyCharm нажмите на кнопку **Add Configurations...** (или **Edit Configurations...**).
2. В левом верхнем углу открывшегося окна нажмите на плюс **`+`** и выберите **Python**.
3. Заполните параметры конфигурации:
   * **Name:** `sitewomen` *(любое понятное имя)*
   * **Script path:** Укажите полный путь к файлу `manage.py` вашего проекта.
   * **Parameters:** `runserver` *(именно эта команда передается файлу `manage.py`)*
   * **Working directory:** Путь к папке проекта, где лежит `manage.py`.
4. Нажмите **Apply** и **OK**.

Теперь проект можно запускать не через обычный терминал, а кнопкой с жуком 🪲 (**Debug 'sitewomen'**) на верхней панели PyCharm.

## ⚠️ Важные нюансы и подводные камни при отладке

### 1. Подводный камень: «Порт уже занят» (Самая частая ошибка)
Перед тем как нажать на «жука» 🪲, **обязательно остановите сервер в обычном терминале** (нажмите `Ctrl + C` в консоли). 
* **Почему это происходит:** Локальный порт `8000` может быть занят только одним процессом. Если вы оставите работать обычный сервер и запустите дебаггер, PyCharm выдаст ошибку, либо точки останова просто не будут срабатывать.

### 2. Как проверить, что дебаггер работает?
Поставьте **точку останова** (кликните мышкой на серое поле левее номеров строк кода во `views.py` — появится красный кружок) на строчке с `return HttpResponse(...)`. 
Затем перейдите в браузере на эту страницу. Программа «замрет», страница в браузере начнет бесконечно крутиться, а внизу в PyCharm откроется панель дебаггера со всеми внутренностями запроса.

### 3. Исправление терминала в Windows (Если PowerShell «глючит»)
В свежих версиях PyCharm встроенный терминал по умолчанию использует PowerShell. Если команды активации виртуального окружения или запуска сервера выдают системные ошибки доступа, смените его на классическую командную строку `cmd.exe`:
* Перейдите в **File** → **Settings** (Настройки).
* В поиске наберите слово **Terminal**.
* В поле **Shell path** замените значение на `cmd.exe`.
