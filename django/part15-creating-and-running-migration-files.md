# Миграции в Django

## Что такое миграции?
**Миграция** — это отдельный файл (Python-модуль) в папке `migrations` текущего приложения. Он содержит команды на уровне ORM для создания, изменения таблиц в базе данных (БД) и связей между ними.

* **Принцип работы:** каждый новый файл фиксирует только изменения, произошедшие в моделях с момента прошлой миграции.
* **Контроль версий:** миграции позволяют легко откатиться к предыдущей версии структуры БД, если в процессе разработки потребовались правки.
* **Важно:** веб-сервер не создает таблицы автоматически. При каждом изменении любой модели нужно вручную обновлять и применять миграции.

---

## Основные команды (выполняются из корня проекта)

### 1. Создание файла миграции
```bash
python manage.py makemigrations
```
* **Что делает:** анализирует модели и создает файл миграции (например, `0001_initial.py` в папке `women/migrations/`).
* **Внутри файла:** описываются инструкции вроде `CreateModel` (создание таблицы со всеми полями, включая автоматическое поле `id`).
* **На этом этапе:** изменения в саму БД **еще не внесены**.

### 2. Просмотр SQL-запроса (опционально)
```bash
python manage.py sqlmigrate <имя_приложения> <номер_миграции>
```
* **Пример:** `python manage.py sqlmigrate women 0001` (указывается только порядковый номер, без `_initial.py`).
* **Что делает:** выводит в консоль чистый SQL-код, который будет выполнен при применении этой миграции (зависит от выбранной СУБД).

### 3. Применение миграций к БД
```bash
python manage.py migrate
```
* **Что делает:** выполняет все непримененные миграции (как ваши, так и стандартные для админки, авторизации, сессий и т.д.) и реально создает/обновляет таблицы в БД.
* **Именование таблиц:** формируется по шаблону `<имя_приложения>_<имя_модели>` (например, `women_women`).
