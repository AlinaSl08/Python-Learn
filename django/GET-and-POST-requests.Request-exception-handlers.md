# GET/POST-параметры и обработка исключений в Django

## 1. Передача параметров через URL (GET и POST запросы)

* **Синтаксис GET-запросов:** Дополнительные данные передаются в адресной строке после символа `?` в виде пар `ключ=значение`, разделенных амперсандом `&`.
  * *Пример:* `http://127.0.0`
* **Доступ к данным в Django:** Все переданные параметры сохраняются в специальном словаре `QueryDict` внутри объекта запроса `request` (`HttpRequest`).
* **Обработка GET-запросов:** Для получения данных используется коллекция `request.GET`. Наличие параметров можно проверить простым условием `if`:
  ```python
  def categories_by_slug(request, cat_slug):
      if request.GET:
          print(request.GET)  # Выведет: <QueryDict: {'name': ['Gagarina'], 'type': ['pop']}>
      return HttpResponse(f"<h1>Статьи по категориям</h1><p>slug: {cat_slug}</p>")
  ```
* **Обработка POST-запросов:** Используется для передачи данных из HTML-форм. Механизм работы полностью аналогичен GET-запросам, но вместо `request.GET` используется словарь `request.POST`.

## 2. Обработка исключений и страница 404

### Настройка боевого режима (`settings.py`)
Пользовательские страницы ошибок работают **только при отключенном режиме отладки**. Для проверки в файле конфигурации `settings.py` необходимо изменить две настройки:
1. Установить `DEBUG = False`.
2. Указать разрешенные домены в списке `ALLOWED_HOSTS`, например:
   ```python
   ALLOWED_HOSTS = ['127.0.0.1']
   ```

### Переопределение обработчика 404
* **Назначение обработчика (`urls.py` проекта):** В главном файле маршрутизации переопределяется переменная `handler404`, которой присваивается ссылка на функцию-обработчик:
  ```python
  handler404 = page_not_found
  ```
* **Функция представления (`views.py`):** Должна принимать два обязательных аргумента (`request` и `exception`) и возвращать объект класса `HttpResponseNotFound`:
  ```python
  from django.http import HttpResponseNotFound

  def page_not_found(request, exception):
      return HttpResponseNotFound('<h1>Страница не найдена</h1>')
  ```

### Принудительный вызов исключения 404
В любом представлении можно искусственно вызвать ошибку 404 с помощью исключения `Http404` (из модуля `django.http`). Django автоматически перенаправит пользователя на единую функцию `page_not_found`:
```python
from django.http import HttpResponse, Http404

def archive(request, year):
    if year > 2023:
        raise Http404()
    return HttpResponse(f"<h1>Архив по годам</h1><p>{year}</p>")
```

## 3. Другие стандартные обработчики ошибок

В главном `urls.py` можно аналогичным образом переопределить поведение сервера для других HTTP-ошибок (активны только при `DEBUG = False`):

| Обработчик | Код ошибки | Значение и причина возникновения |
| :--- | :--- | :--- |
| **`handler400`** | `400 Bad Request` | Невозможно обработать некорректный запрос от клиента. |
| **`handler403`** | `403 Forbidden` | Доступ к запрашиваемому ресурсу запрещен (недостаточно прав). |
| **`handler404`** | `404 Not Found` | Запрошенный URL-адрес не найден в маршрутах проекта. |
| **`handler500`** | `500 Server Error` | Внутренняя ошибка сервера (ошибка выполнения кода в представлении). |
